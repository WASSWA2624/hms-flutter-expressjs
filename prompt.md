Refine the implementation of the "Next Step" action across the application:

- Focus exclusively on making every "Next Step" value in all patient workflow tables a clear, actionable button, not just informational text.
- This action button must always open the correct dialog or form corresponding to the next required step, using existing shared dialog components where possible. It should never route to a generic page unless absolutely necessary for correct workflow.
- If a step (e.g., "Pay consultation") is only permitted within a particular module (such as Billing), and the button is pressed in a different context (such as OPD), it must navigate the user directly to the appropriate module or open the relevant dialog there.
- For each workflow step:
  - **Pay consultation:** Open the pay consultation dialog with encounter details pre-filled, from the authorized module (usually Billing).
  - **Start encounter:** Open the start encounter dialog.
  - **Triage:** Open the triage form dialog.
  - **Assign doctor:** Open the doctor assignment dialog.
  - **Lab order:** Open the lab order request dialog.
  - **Lab results ready:** Open the clinical details dialog displaying lab results.
  - **Dispense medication:** Open the medication dispensing dialog.
  - **Radiology scan/request:** Open the radiology request dialog.
  - **Radiology report ready:** Open the clinical details dialog displaying the radiology report.
  - **Admit patient:** Open the admit patient dialog.
  - **Assign beds:** Open the bed assignment dialog.
  - **Nursing assessment:** Open the nursing assessment dialog, pre-filled as needed.
  - **Physiotherapy session/request:** Open the physiotherapy session or request dialog.
  - **Insurance pre-ops:** Open the insurance pre-op dialog.
  - **Close encounter:** Trigger the close encounter flow or dialog.

- All dialogs and forms should be pre-filled using relevant patient, encounter, or action identifiers.
- Audit the entire application (front end and backend) to ensure:
  - The list of next-step actions is exhaustive—review all workflow tables and known step transitions;
  - Every required dialog already exists and is reused; if a dialog does not exist, it must be created;
  - Each table or workflow context that displays a "next step" column always presents the action as a button, wired to the proper handler/dialog.
- Expand and update the action-step registry or resolver so that all real workflow transitions in the app are covered.
- Update the backend and front-end where necessary to ensure every next-step action and step can be completed through the correct UX pattern.
- Remove any obsolete or resolved actions from the registry or lists so only up-to-date steps and actions remain.
- The goal: Users must always be able to complete the next workflow step from any relevant table by clicking the button, which opens the appropriate dialog or navigates as required, always showing the latest and correct data context.
